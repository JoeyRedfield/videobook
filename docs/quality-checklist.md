# VideoBook 质量检查清单

这份清单用于交付“完整详细笔记”。它把视频重构成可检索的书面章节，但不会把课程压缩成只列结论的摘要。用户明确要求“提炼核心观点”时，才切换到摘要产物。

## 1. 内容完整性

- 先记录视频总时长、字幕末段时间和章节边界；按固定时间块顺序阅读完整字幕，不只阅读开头、章节标题或模型自动提取的要点。
- 每个时间块都应能在 `book.md` 找到对应的章节、小节、例子、推理或操作结果。可以合并口癖和纯重复，但不能删除铺垫、类比、案例、失败过程、代码步骤和结论依据。
- 用字幕时间范围与书中时间锚点做一次覆盖审计。字数、章节数和截图数都不能单独证明覆盖完整。
- “完整详细笔记”和“提炼核心观点”是两种不同交付物；默认按前者执行。

## 2. 生成顺序

按下面的串行顺序执行，避免占位符、截图和正文互相覆盖：

```text
transcript.json
    ↓
定稿 book.md（正文、时间锚点、Mermaid、SCREENSHOT/SLIDE 占位符）
    ↓
生成 transcript.corrected.txt 和 book.tagged.md
    ↓
截帧并物化图片
    ↓
生成 book.html
    ↓
浏览器 QA
    ↓
发布并核对线上文件
```

`book.md` 定稿前不要截帧或物化；截帧期间也不要并行改写同一个 Markdown 文件。

## 3. 截图和图表检查

- 抽查至少一张幻灯片帧和一张演示帧：画面必须来自正片对应时间，不能是广告、推荐层、播放器 UI、黑帧或低清首帧。
- 检查截图内容是否真的支持相邻文字；文件存在、文件大小正常并不等于画面正确。
- Mermaid 不能只停留在 Markdown 代码块中。必须在实际生成的 HTML 中看到对应的 SVG；图片使用懒加载时，先滚动或触发加载再检查自然尺寸。
- 若使用课程官方幻灯片，运行 `python src/course_assets.py <video_id> --audit`，确认每页恰好出现一次。

## 4. 浏览器和移动端 QA

在真实浏览器中检查生成的 `book.html`：

- 目录链接、时间锚点、视频卡片、图片点击放大和 Esc/空白处关闭均可用；
- 所有 Mermaid SVG 和截图都已加载，没有裂图、黑块或横向滚动；
- 桌面和手机视口都检查一次，特别关注长表格、长函数名、代码块和时间轴；
- 页面颜色对比度满足 WCAG AA（至少 4.5:1）。

## 5. 发布后核验

- 等待 Pages 部署完成后再检查，不把 `git push` 成功当作发布成功。
- 比较线上 `book.html`、`book.md`、字幕对照稿和截图数量/文件名与本地成品；随机打开目录、图片和 Mermaid 图。
- 发布前运行 `git status --short --ignored` 和公开内容隐私扫描，确认没有绝对路径、代理地址、Cookie、登录态、主机信息或运行缓存。

## 6. 最小验证命令

```bash
uv run pytest -q
git diff --check
git status --short --ignored
git grep -n -E '/Users/|127\.0\.0\.1:7890|cookies|capture-profile' -- '*.md' '*.py'
```

这些命令验证仓库状态和公开文本；视频内容、截图画面、Mermaid SVG 和线上页面仍必须按上面的人工浏览器清单检查。
