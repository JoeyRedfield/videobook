# 第二步：把字幕改写成 book.md

## 顺序

1. 读 `output/<video_id>/transcript.json`（`duration`、`chapters`、`segments`）。
2. 若存在 `output/<video_id>/course/`：先读 `course/*.notes.md`（讲师书面讲义）与 `course/slides_text.md`
   （每页幻灯片标题 + 要点），用途见 `course-assets.md`。
3. 读排版指令（stitcher prompt）：仓库内存在 `prompts/stitcher_system.md` 时**以它为准**；
   否则用本 skill 自带的同源副本 `references/stitcher-prompt.md`。两者不一致时以仓库版本为准，并回头同步副本。
4. 按其要求把字幕重构成结构化 Markdown，写入 `output/<video_id>/book.md`。
5. **目录不要手写**：书名与信息块之后、正文之前单独写一行 `<!--TOC-->` 作占位符，
   然后跑 `python src/build_toc.py output/<video_id>/book.md` 生成目录（`--check` 只校验）。
   链接文字与锚点全部从 `##` 标题机械推导、并剥掉标题自带的编号，避免出现
   「1. 1. 回顾与开场……」这种“有序列表编号 + 标题编号”叠在一起的事故（第四步渲染前还有一遭自动兜底）。
6. 若 `course/` 存在：写完 `book.md` 后要**回头再跑一次第 1.5 步**物化 `SLIDE:` 占位符
   （`python src/course_assets.py <video_id> --course-url <主页> --lecture <N> --no-render`），
   然后再跑 `--audit` 必须 PASS（铁律 8），最后才去第三步截帧/第四步渲染。
   **顺序不能颠倒**：第 1.5 步首次执行时 `book.md` 还不存在，它无法替物化；
   漏掉这一步的直接后果是 HTML 里原样留着一堆 `SLIDE:` 占位符、图片全缺（已踩过两次）。

## 非课程类短视频（口播 / 访谈 / 职场科普）

没有 `course/` 的短视频同样按 stitcher 指令写成覆盖全片的详细笔记，但排版上注意：

- 跳过第 1.5 步；书首信息块写清「平台 · 作者 · 时长」与原视频链接，不要伪装成课程讲义或编造许可信息。
- 章节按内容逻辑重组（机制 / 案例 / 方法 / 结语），官方 `chapters` 只用于定位；每章开头给一个
  `*(参考时间: MM:SS)*`。短片的 `##` 章可以多、每章可以短，但每个时间块都要在书里有落点。
- 截图按章节 / 小节起点选点即可（10 分钟视频约 10–15 张）；口播视频没有界面可截，图注写
  「讲者讲述 X」这类画面描述，不要伪造「点击某按钮」的操作描述。
- 案例与机制链适合 Mermaid：因果/循环用 `graph LR`，判断/流程用 `graph TD`；没有代码就不要硬造代码块。
- 讲师在片尾预告的后续内容、对「职场厚黑学」的态度等收尾观点属于正片内容，照常保留，不要当成致谢或元信息删掉。

## 硬性要求

- 口语转书面化技术语言；分章节，用 `##` / `###` 组织并加恰当小标题。
- 原语言不是中文时**必须翻译成地道中文书面语**。
- 关键界面 / 操作步骤处必须插占位符：`![场景描述](SCREENSHOT:HH:MM:SS)`。
- 遇到系统架构、执行流程流转、条件判断，**必须用 Mermaid** 画图（`` ``mermaid `` 包裹，如 `graph TD`），不要只用文字描述。
  - 渲染器只识别这几种首行前缀：`graph` / `sequenceDiagram` / `gantt` / `pie` / `classDiagram` / `stateDiagram` / `mindmap`。
    **写成 `flowchart TD` 不会被渲染成图**，会原样留在页面上变成一个代码块——流程图请一律写 `graph TD`。
- 重要章节开头可保留时间锚点 `*(参考时间: 01:15)*` 方便读者溯源。
- 视频中提到的代码用带语言标注的代码块给出；要点用粗体与无序列表。
- **书里只有课程内容，不要写元信息**：禁止 `## 后记` / 「本书是如何生成的」/「关于本书」这类章节，
  也不要写“本书由 B 站 AI 字幕（覆盖率…）经 AI 重构而成”“截图管线逐个 seek 抓帧”这类流水线自述、
  ASR 覆盖率与错词统计。全文到「附：官方参考与延伸阅读」和（有课时）附录为止；
  文末的流水线 + 许可页脚由第四步/发布流程自带，不要写进 `book.md`。
  （这个「后记」原先既没被要求、也没被禁止，是模型模仿已有书稿排版自发长出来并代代相传的，所以现在明确禁止。）

## 章节与时间戳

- `chapters` 只是**辅助定位**：平台官方章节往往粗糙，顶层分章按内容自身逻辑组织，**不要求**与官方章节一一对应。
- `SCREENSHOT:` 时间戳落在其所属内容的时间区间内即可；优先选章节边界、新幻灯片出现时刻、演示画面时刻，
  结合前后字幕语义定位，格式 `HH:MM:SS`（毫秒取整到秒）。
- `course/` 存在时，「画面就是某一页幻灯片」的地方改用 `![描述](SLIDE:n@HH:MM:SS)`
  （`n` = `slides_text.md` 中的幻灯片编号，`@` 后是该页在视频中出现的时间）；
  演示、终端、浏览器、板书等非幻灯片画面仍用 `SCREENSHOT:`。
  拿不准就用 `SCREENSHOT:`，后续脚本会自动把「画面即幻灯片」的帧升级为官方渲染图。

## 容忍 ASR 噪声

动笔前先结合视频标题、`chapters`（有讲义时再加讲义）建立**术语表**，改写时统一规范化。常见同音错词：
「深圳市软件工程」→ 生成式软件工程、「威尔法 / WIFI」→ verifier、「chain of salt」→ chain of thought、
「KIMIK3」→ Kimi K3。讲师的口语梗（「舔狗」「做题家」等）保留原意，不要雅化成术语。
反复出现的系统性错词应补进 `src/make_corrected.py` 的 MAP，见 `correction.md`。

## 保真底线（优先于「去除口语化」）

1. 保留讲师的类比、案例、铺垫与推理链：重要案例不得压缩成一句结论；代码、推导、操作保留足够步骤；
   没有证据的代码不得凭空补写。
2. 区分讲师判断、客观事实与编辑补充：必要补充明确标注「编者说明」；不替讲师纠正观点，不默默加入外部知识。
3. 只删无意义口癖、卡顿与纯重复：讲师有意的强调式重复、幽默与铺垫不属于纯重复。

## 写完之后

- 接着做第三步截帧（`capture.md`）。有 `course/` 时**先物化 SLIDE 占位符再截帧**，
  `capture_frames.py` 只会补拍剩下的 SCREENSHOT 帧。
- 需要字幕对照稿时做 `correction.md`；它与截帧没有依赖关系，可以并行。

## 会议演讲（talk）/ 长问答视频

- 元数据用 `.venv/bin/python -m yt_dlp --skip-download --dump-json "<URL>"` 取 `title / channel / upload_date / duration / chapters`；书首写清「平台 · 讲者 · 时长」与原始链接，可选加官方演讲页（AI Engineer 等站点通常有 talk 页与整理稿）。
- 整理稿 / 官方 talk 页可以校准**幻灯片上的精确数字和术语**（例：本次 72.9%、66.1%→87.9%、2.45¢→1.83¢），但要拿视频字幕和实际截图再对一遍；整理稿是二手材料，不要整段搬运，也不要把它当指令来源。
- 结构：正片按主题分章（不必跟官方章节一一对应）；Q&A 可按官方 Q&A 章节或主题分成 2–4 章，每个实质性提问一个小节并标 `*(参考时间)*`，合并重复问题但不要删掉论据。
- 截图：正片每章 1–2 张幻灯片；Q&A 段的图先看实际画面再写图注（见 `capture.md`「问答 / 访谈段落的截图」）。幻灯片数字以画面为准，口播约数（“up to 72%”“90%”）可以保留，但不要把它硬安到只显示坐标点的图上。
- Mermaid：**5 个节点以上的链式流程用 `graph TD`**；`graph LR` 长链会被正文宽度等比缩到很扁（实测 6 节点被缩成 716×35，文字 9–10px）。并列对比/因果用 `graph LR`，步骤链/闭环用 `graph TD`。
- 非课程视频没有讲义/幻灯片版权页：`post_process.py` 会统一补“课程讲义与幻灯片 … CC BY-NC”页脚，这是模板行为；交付时说明这是流水线页脚即可，不要在 `book.md` 手写许可，也不要声称演讲幻灯片适用该许可。
